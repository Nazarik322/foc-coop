> **Ранняя dev-версия.** Это proof of concept, а не готовый мод. Возможны вылеты, глюки графики и
> недостающие функции. Файлов игры в репозитории нет, нужна своя копия игры.
> Проект не связан с Hasbro, High Moon Studios и Activision.

Кампания Fall of Cybertron одиночная, а официальные онлайн-сервисы игры не работают. Проект добавляет
кооператив поверх штатной репликации Unreal Engine 3 по прямому IP. Это один `dinput8.dll`, который
загружает игра; он добавляет **меню прямо в игре** (клавиша **F10**) для создания и подключения к играм.

Поддерживаемый билд: Steam, `TFOC.exe` SHA-256
`c1dab177f81503ecb831d63a3d799f928dd9823242ca3689482c684396acfedc`.

## Установка

1. Скопируйте папку с игрой (установку Steam не патчьте) или сохраните `Binaries\dinput8.dll`, если он есть.
2. Положите `dinput8.dll` (из `launcher/payload/` или своей сборки) рядом с `TFOC.exe` в `Binaries`.
3. Запустите `TFOC.exe`. Если файла `foc_coop.ini` нет, автоматически используются настройки для кооператива.

## Меню в игре

Нажмите **F10** в главном меню или в матче; **Esc** или **F10** закрывает его. Пока меню открыто, игра не
получает клавиатуру и мышь.

| Страница | Что делает |
|---|---|
| **Host a game** | Выбор *Story* (глава) или *Escalation* (карта), максимум игроков (2-5), кнопка *Start hosting*. |
| **Join a game** | Список лобби в вашей сети (имя хоста, режим, карта, игроки, адрес) и поле ручного ввода IP / порта. |
| **Leave to main menu** | Остановить игру / выйти из сессии. |
| **About / status** | Состояние движка, последняя команда, имя экземпляра, экспериментальный переключатель *fast travel*. |

Создание игры и подключение **перезапускают игру** сразу в сессию (около 20-30 секунд). Открыть карту из уже
запущенного главного меню игра не даёт: её мёртвый онлайн-слой выдаёт «You must be signed in to play online»,
а карта из командной строки работает, поэтому меню перезапускает игру с нужными аргументами.

Лобби объявляются широковещательным UDP по локальной сети. Для игры через интернет нужен VPN (или проброшенный
порт), адрес хоста вводится на странице *Join*. Настоящего подбора игр через интернет нет.

## Что работает (проверено)

Проверено на двух копиях игры на одном ПК, хост и гость, через меню:

| Режим | Результат |
|---|---|
| **Escalation**: Ark, Gladiator, Iacon, Temple | Работает на двоих: оба заходят в матч, выбирают персонажей и играют. |
| **Сюжет, глава 1 (The Exodus)** | Работает на двоих (вступительный ролик, туториал, rescue-телепорт для гостя). |
| **Сюжет, главы 6 (Megatron) и 8a (Starscream)** | Оба игрока в геймплее, у каждого своя камера и HUD. |
| **Сюжет, главы 3a и 4a** | Оба игрока в начальном ролике; геймплей после него не проверен. |
| Меню в игре, список лобби, хост и подключение, перезапуск в сессию | Работает. |

## Что не работает / известные проблемы

- **Сюжет, главы 2a, 2b, 3b, 4c, 8b, 9: гость подключается, но персонажа не получает** (смотрит на небо, нет HUD).
  Скрипты уровней создают только одного героя; создание персонажа для второго игрока ещё не сделано.
- **Глава 5 (Soundwave): хост упал меньше чем за минуту** в тестовом прогоне.
- **Глава 4b** у обоих игроков показала ролик; геймплей не проверен.
- **Графика гостя**: в роликах персонажи у гостя выглядят тёмными силуэтами.
- **Гость в главе 1 начинает «повержённым»**, выручает rescue-телепорт.
- **3-5 игроков** не проверены (тестировались только двое).
- **Запуск сессии без перезапуска** игра отклоняет, поэтому меню перезапускает игру.
- Поддерживается только Steam-билд с указанным хешем. Только Windows (игра 32-битная).
- Ролики и скриптовые события синхронизируются частично. Режимы версуса не пробовались.

## Настройка

Необязательный `foc_coop.ini` рядом с exe, секция `[foc_coop]`. **Без этого файла все функции кооператива включены.**

| Ключ | Действие |
|---|---|
| `instance=B` | Суффикс мьютекса единственного экземпляра и имени игрока, чтобы запускать несколько копий на одном ПК |
| `tcpdriver=1` | Использовать `IpDrv.TcpNetDriver` вместо драйвера Demonware |
| `forcechar=1` | Принудительно «персонажи загружены» (чтобы выйти с экрана загрузки Escalation) |
| `maxplayers=N` | Лимит игроков на хосте |
| `tutguard=1`, `skiptut=1` | Защита и патчи туториала, который роняет хоста кампании |
| `ctrlshare=1`, `hostfirst=1` | Общие контроллеры и порядок «хост первым» (кампания) |
| `rescue=1` | Телепорт упавшего персонажа к другому игроку |
| `ctrldiag`, `scan`, `dump`, `trace`, `lp` | Диагностика и эксперименты, пишут дополнительные логи |

Всё пишется в `foc_coop.log` рядом с exe (сетевые вызовы, действия меню, исключения).

## Как это работает

Прокси `dinput8.dll` лежит рядом с `TFOC.exe` и загружается вместо системного. Он:

- перехватывает Direct3D9 (`IDirect3D9::CreateDevice`, затем `EndScene` устройства) и рисует меню через Dear ImGui,
  а пока меню открыто, обнуляет состояние DirectInput;
- переключает сетевой драйвер на TCP/IP в загруженных строках конфига, поднимает лимит игроков и ставит
  `TnLocalPlayer._CharactersLoaded`;
- патчит логику туториала, роняющую хоста кампании, раздаёт и упорядочивает контроллеры, чтобы гость мог заспавниться;
- объявляет созданные игры широковещательным UDP (порт 47799) и показывает их на странице подключения;
- умеет вызывать `Exec` движка (`open <url>`) в игровом потоке (экспериментальный *fast travel*).

## Сборка

- `build.bat` (Visual Studio 2022 Build Tools, x86) собирает `build\dinput8.dll` из `src/proxy_dinput8/`
  (`dinput8.cpp` и `overlay.inc`; Dear ImGui лежит в `third_party/imgui`, лицензия MIT).
- `launcher/FoCCoop.exe` — маленький **инструмент разработчика**: ставит DLL в тестовые копии и запускает сессии
  из командной строки; игрокам он не нужен. Это один C#-файл, компилируется штатным `csc.exe` из .NET Framework.
- `tools/dev.ps1`, `tools/e2e_menu.ps1`, `tools/matrix.ps1` управляют двумя копиями игры в тестах (настоящие
  события клавиш и мыши, скриншоты, прогон по картам). `lpdiff.py` и `snapdiff.py` сравнивают снимки памяти.
